# 为什么 oGMemory 的 QA token 高于 M3-Agent

范围：最新已完成的八视频配对子集、97题，源实验
`m3_ten_fullinterval_20261102`。两道原始超时保留，不混入恢复答案。
本页分析冻结版本 `8d61b772`，不将后续人物绑定或并发复测归入结论。
派生指标见 `experiments/m3_paper_paired8_20261103/token_gap.json`。
这是日志和代码诊断，不是新增付费模型实验。

## 1. 差距主要在问答，不在建忆

| 已记录输入+输出 token | oGMemory | M3-Agent |
|---|---:|---:|
| 建忆 | 3,294,852 | 3,620,387 |
| QA | 4,151,184 | 778,834 |
| 合计 | 7,446,036 | 4,399,221 |

建忆用量并非 oGMemory 更高；M3 的建忆输出（包含推理）反而更多，
但这不能直接推断其最终存储的记忆文本更长。
主要问题是问答如何检索、组织和重复消费已有记忆。
M3 建忆有一次请求未返回 usage，因此其建忆/合计是已知量，非完整账单；
合计约1.69倍只能描述已记录量。两边QA的usage完整。

## 2. 调用次数不是主要倍数来源

| QA 指标 | oGMemory | M3-Agent |
|---|---:|---:|
| 输入 token | 4,039,490 | 733,810 |
| API调用次数 | 525 | 398 |
| 每题平均调用 | 5.41 | 4.10 |
| 每次平均输入 | 7,694 | 1,844 |
| 各题首次调用平均输入 | 1,514 | 454 |
| 各题末次调用平均输入 | 13,057 | 2,624 |
| 记录进入第6轮的题数 | 74/97 | 42/97 |

精确的总量分解为：

```text
输入比 = 调用次数比 × 平均每次输入比
5.5048 = 1.3191 × 4.1732
```

这是描述性分解，不是两个独立因素的因果归因：检索策略同时影响轮次与上下文。
首轮还没有检索证据时就存在差距，说明系统提示/工具协议也有开销，
但不能只归因于工具 schema；更主要的现象是检索后上下文持续增长。

## 3. 我们倾向于广召回、大量交付，而 M3 的普通路径更节制

冻结的 M3 参考适配普通 clip 检索设为 top-2，并维护已经交付的片段。
oGMemory 同时使用片段、转写、事实索引、相邻上下文；Search 审计平均返回17.1个节点。
返回节点不等于全部发送：有相应上下文审计的95题中，首次检索后平均实际选择
8.7个来源节点、33.4个原文位置；最终模型视图平均包含144.7个原文位置。

这些是来源位置，不是同等数量的独立有用事实。一个动作可能同时出现在描述、
事件项和转写中：按位置去重能阻止相同位置重传，但不会自动消除跨字段语义重复。
因此下一步重点不是继续节省 JSON 标点，而是减少无关证据和重复表达。
以上支持“交付较宽”的诊断，不证明每条额外证据都无用。

## 4. 严格增量不等于 API 只计新增 token

当前实现保留已交付工具消息。新增事实只附加一次，解决的是“同一位置重复准入”；
后续请求仍包含保留的历史，API prompt usage 仍统计这部分上下文。
若基础提示为P、共T轮，每轮新增约d个token且不淘汰，则累计输入近似为：

```text
T × P + d × T × (T − 1) / 2
```

公式忽略控制消息等开销，仅说明早期大段交付会被后续多轮反复消费。
即使消息前缀稳定，总输入也不会只等于“首次基础提示 + 所有新增证据”。

缓存部分占输入的47.3%（oGMemory）和64.2%（M3）；
未缓存输入为2,128,535和262,922，相差8.10倍。
不能据此断言供应商缓存实现或费用倍率：缓存行为不是受控单因素实验。
这批记录没有上下文 epoch 重建，故不宜把差距简单归咎于重建破坏前缀。

## 5. “新增证据”与“回答进展”存在错位

代码以新增可见来源位置重置 no-gain 计数；广召回只要还能带回一个新位置，
即使对当前问题帮助很小，也不会被判为无进展。
这批审计没有触发基于连续无新增可见事实的收尾，
而74题记录了末轮收尾。该组合提示：停搜信号可能过宽，值得单独验证。
它不证明强制提前回答一定正确，也不能由轨迹相关性直接推出质量因果。

## 建议的验证顺序

1. **先改交付策略。** 保持后台候选召回较宽，但先交付top-2/top-4紧凑来源事实，
   相邻片段、完整转写和原文细节按需补充；计数、跨时段题允许扩展。
2. **再验证更小的新增额度。** 同一记忆、同一97题对比3500与1000–1500代理计数单位。
   保留总预算，记录每轮新增证据、质量与失败，不预设收益。
3. **区分位置新颖与问题进展。** 检查人物、对象、时间、位置等待解决条件是否得到
   支持，而不只问“是否出现新位置”。优先利用现有控制调用，不额外增加一个昂贵裁判。
4. **保留原文层，提供精简读取视图。** 用必要事实、时间与短引用先回答，详细原文留作
   可追溯展开。语义去重必须保留不同时间的重复事件，不能误伤计数问题。
5. **把新人物关联作为待测假设。** 它可能减少人物歧义和无关检索，也会增加建忆图片输入；
   必须独立检查QA节省与质量，不把旧八视频结果当作其收益。

固定记忆的QA消融即可先检验上述策略，不需要重新处理视频或重跑M3-Agent。
当前分数优势为0.5722对0.4381，但不是等token预算对照；
不能据此声称我们按token衡量更高效，也不能盲目缩小top-k来换表面成本下降。
并发主要影响墙钟时间，不会自动减少同一上下文的token消耗。
