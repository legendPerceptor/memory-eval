# 算子贡献与人脸聚类扩展性：代码审计和消融计划

日期：2026-11-03。针对当前十视频实验冻结版本`8d61b772`与实际配置。
仅做代码审阅、已有日志统计和实验设计；不更改当前任务、不启动额外付费消融。

## 1. 成本贡献不等于质量贡献

前八视频97题的oGMemory路径总时间为688.39分钟（各方法分别计入一次共享感知，排除评委）。
其中：

| 阶段 | 分钟 | 总时间占比 |
|---|---:|---:|
| 人脸聚类 | 309.29 | 44.93% |
| 情景记忆生成 | 257.89 | 37.46% |
| QA | 65.91 | 9.58% |
| 人脸检测/特征 | 13.40 | 1.95% |
| 说话人分离 | 11.12 | 1.62% |
| ASR | 6.65 | 0.97% |
| 其他阶段合计 | 24.12 | 3.50% |

这是阶段墙钟分解，含I/O、初始化、远端等待等，不是纯GPU/CPU计算。
人脸聚类时间包含每次新增视频后对整个账号累计人脸的重算，不能当成独立视频聚类成本。
完整算子时间数据见同名JSON。现有结果不能给出每个算子的质量百分比。

## 2. 当前数据依赖：人脸检测与人脸聚类必须分开

### oGMemory当前问答路径

- `m3/episodic_memory.py::generate_episodic_for_clip`传入原始帧、可选原始音频和ASR；
  `EpisodicMemoryGenerator._build_messages`不读取人脸聚类/声纹聚类。
- 说话人分离给ASR添加的speaker_id确实进入提示，是实际的信息输入。
- 默认QA检索`episodic_memory_generator`类ExtractedNode，结合转写、事实索引与邻近片段。
- `m3/control_adapter.py`的`identity_aware`调用`rank_identity_candidates`，利用姓名/角色文本，
  不读取SAME_IDENTITY边。
- 默认QA未将视频级MemoryNode汇总作为直接检索入口。

**代码审计结论：没有找到oGMemory人脸聚类结果进入当前默认情景生成或QA的直接消费路径。**
这是对当前实现的结论，不是“所有人脸聚类都无用”，也不是实测质量贡献恰为0%。
关闭该分支预计不改变直接QA输入，但仍应通过隔离副本、查询重放及调用/证据指纹验证。

### M3-Agent参考适配

`comparisons/m3_agent_matched/runner.py::prepare_clips`读取`faces.jsonl`与
`speaker_embeddings.jsonl`，以M3自己的VideoGraph维护人脸/声音锚点，并传入标识化
人物裁剪及说话人转写。它不读取oGMemory的`face_clusters.jsonl`或其身份边。

因此：
- 关闭oGMemory的全账号face_clustering，不等于关闭M3的人物能力。
- 关闭共享detect_faces会改变M3的输入，不能作为无影响的提速措施。
- speaker_embedding在当前oGMemory直接提示中未被使用，但M3适配确实消费它。
- 后置voice_segmentation不是ASR内部的VAD，不能把两个组件混为一谈。

## 3. 如何避免重复全量聚类

### 优先级A：只同步计算有消费者的产物

把流程分成“当前QA最小必要链路”和“身份图增强链路”。对没有消费者的图谱增强步骤，
支持显式关闭或异步构建；保留功能本身及版本记录。先用离线重放确认
删除/屏蔽这些输出不会改变同一固定查询的候选、上下文和提示。
不能以“程序还能运行”代替质量验证；后续真接入身份边检索时再同步启用。

### 优先级B：按任务声明聚类范围

M3-Bench题目只依赖单个视频，因此评测中可提供video级聚类模式；
跨视频长期记忆应用则应明确使用collection/stream/account范围，不能一律禁掉跨视频身份。
namespace至少包含租户、作用域、感知模型版本和匹配策略版本。
新增一个无关视频不应导致所有独立评测视频重新进行全局聚类。

按视频聚类改变了身份关系的允许范围，不应宣称与account级图语义等价；
应在独立配置中验证，并保留原配置结果。

### 优先级C：同一作用域内做持久化增量聚类

旧人脸N个，新增m个且旧向量/阈值/约束不变时：
1. 保存旧节点、已计算的连接分量、代表信息、版本和已处理游标。
2. 只计算新—旧与新—新相似度，不再比较旧—旧。
3. 用新通过阈值的连接更新分量；新脸可能桥接两个旧簇，必须支持旧簇合并。
4. 保存稳定身份ID及别名/规范根映射，并以事务/幂等操作更新关系；不能只把新脸挂在
   某个旧中心后就忽略旧簇之间的新连接。
5. 向量修订、删除、模型/阈值/作用域策略变化需要失效处理或重建，不能继续沿用旧分量。

对于当前阈值图的单链接定义，若新—旧候选完整且使用同样约束，这种追加更新可以保留
已有连接关系；单轮距离计算量从O((N+m)^2)减少到O(Nm+m^2)。
这是追加数据时的设计推导，并非本仓已经实现或测得的速度。

PR #300的分块矩阵乘法可以作为精确计算内核，但仅做矩阵化仍是全量算法，
并未自动消除每视频的重复旧—旧比较。持久化增量状态才解决重复计算本身。
近似向量召回/只与簇中心比较是进一步的性能—质量取舍：可能漏掉连接或改变单链接结果，
不能标成严格等价；需评测漏合并、错合并及下游回答变化。

现有cache依赖全部人脸集合的完整指纹，新增人脸就改变指纹，而且默认位于各视频工作目录。
这主要服务于相同输入重跑，不能当成跨视频增量算法。

## 4. 如何量化各算子的质量贡献

### 先做依赖审计，再做两层消融

| 组件/能力组 | 当前oGMemory消费者 | 实验方式 |
|---|---|---|
| 抽帧与视觉证据 | 情景生成直接使用 | 固定数量改变采样；或视觉分支消融，重新生成记忆 |
| 原始音频 | 情景生成直接使用 | 原始音频on/off × ASR on/off，区分互相替代与互补 |
| ASR | 情景提示、记忆转写、索引/召回 | 必须移除全部消费路径并重建下游，不能只关闭独立转写检索 |
| 说话人分离 | 转写中的局部speaker_id | 保留转写文本/时间，只去标签后重新生成记忆；不等于关闭音频 |
| 人脸检测/特征 | oG默认直接提示未消费；M3消费 | 两方法分别消融，不能从oG结论推断M3 |
| oG人脸聚类 | 当前QA未发现直接消费者 | 隔离图副本屏蔽产物并重放固定检索，优先验证输入不变 |
| 声纹特征 | M3身份锚点使用 | 与oG后置voice_clustering分开检验 |
| oG后置声纹聚类 | 当前QA未发现直接消费者 | 屏蔽对应身份边，检查消费者与证据不变 |
| 视频级汇总MemoryNode | 默认QA非直接入口 | 先验证不影响当前入口；若要评价效益，应先设计消费路径 |
| 片段向量/转写/事实召回 | QA检索直接使用 | 固定记忆，逐分支关闭；保留剩余可运行检索基线 |
| 姓名/角色软排序 | QA检索直接使用 | 固定记忆，仅切换该开关 |
| 邻近片段补充 | QA证据直接使用 | 固定记忆，关闭邻居扩展 |
| 严格增量交付 | QA模型上下文 | 固定记忆，只改交付，整体安全预算保持不变 |
| 切片、加载、存储等硬依赖 | 支撑整个系统 | 不适合直接删除导致系统不可运行；用有效替代实现或只比较成本 |

第一层是便宜的固定记忆QA消融，回答检索/交付问题；第二层才是感知→记忆→QA的重建实验。
删除QA可见ASR而保留原记忆中的ASR总结，属于信息泄漏式的“假消融”。

### 评价量

对有效且依赖一致的消融，记录条件边际变化：

`ΔScore_i = Score(full) − Score(full without i)`

同时报告：题目配对变化、整体及相关题型得分、有效回答/记忆覆盖、token、阶段耗时和GPU峰值。
保留负值和零值，不把负贡献截成零。使用视频级不确定性描述和少量重复运行评估模型波动，
不要把同视频内题目当作完全独立样本。

**单项消融差值不可相加归一化为“贡献百分比”。** 模块有替代、协同和硬依赖关系；
若确实要做分摊比例，需要先定义可运行的模块组、基线及多种组合实验，
并明确分摊规则及假设。现阶段更可信的表是：算子/能力组、耗时占比、关掉后下降多少百分点、
token变化、输入/证据是否改变、结论置信程度。

## 5. 建议执行顺序

1. 当前十视频维持冻结配置跑完，不在运行中跳过或替换聚类。
2. 完成消费者审计，对疑似未消费的后置分支做无付费模型的固定查询重放。
3. 在独立配置中验证最小必要QA流程；身份图能力保留为可选增强，不删除未验证功能。
4. 在完成的固定记忆上做事实索引、转写召回、人物软排序、邻居与增量交付消融。
5. 再挑感知分支做真正的下游重建，并用独立视频确认收益。
6. 加速PR分别提交作用域治理、等价矩阵化、增量状态与并发调度，避免一次同时更改全部因素。
