# 十视频全片段采样实验

实验目录：`experiments/m3_ten_fullinterval_20261102/`。实际状态以其中
`status.json` 和各阶段回执为准；本文是协议说明，不表示已经跑完。

## 采样修正

- 每个30秒片段按1 fps收集至多30帧，代替此前前缀16帧。
- 情景模型仍接收最多16张基础帧，使用现有均匀索引
  `floor(i * n / k)`，标准30帧片段对应约0至28秒。
- “覆盖全片段时间范围”不是连续看完视频；短暂动作仍可能被稀疏采样遗漏。
- 配置文件和命令行默认值都设为30，防止旧CLI默认16覆盖YAML。
- 原始音频完整提取；人脸检测处理本轮收集的全部帧。
- M3参考适配使用同一基础帧选择器，额外的人脸裁剪仍按原适配设计保留。
- 两方法的基础图片节点ID在运行中逐片段比对。该比对不声称所有提示内容完全一致。

- 固定答案之后共同盲评；打乱256个(method, question)任务，方法名不送评委。
- 报告全十视频、原五视频、新五视频及逐视频结果，缺失/无效回答计零；
  评委服务错误单列，不能当作回答错误。
- 不用旧五视频的前缀采样答案拼接成十视频成绩，不覆写历史论文和评分。

## 运行与复现

初次准备（只允许在目标目录尚不存在时运行）：

```bash
cd /home/yuanjian/Development/memory-eval
source ~/.bashrc
oGMemory/.venv/bin/python scripts/run_m3_ten_video.py prepare
```

执行已经准备好的冻结驱动：

```bash
export M3_EVAL_ROOT=/home/yuanjian/Development/memory-eval
oGMemory/.venv/bin/python runs/m3_ten_fullinterval_20261102/driver.py run
```

**已有后台进程时不要再启动。** 驱动有文件锁，已结束阶段以回执为准。
中断的QA和评分不会直接覆盖或自动择优重试；需先检查状态和已写出的答案。
额度低于12%时在新记忆请求/新问题之前等待，周额度低于5%或准备后24小时
达到安全截止时停止。等待不占用单题推理预算。

- `manifest.json`：抽样、配置、原始视频和冻结代码的指纹。
- `status.json` / `stages/`：整体状态及分视频阶段回执。
- `frame_audits/`：实际抽帧/模型帧时间与节点ID。
- `usage-*.jsonl`：分阶段调用用量，不含提示、响应正文或密钥。
- `private/`：本地配置和日志，不提交Git。
- `joint_questions.jsonl`、`comparison.json`、`REPORT.md`：共同评分完成后生成。

启动早期在任何QA开始前补充了独立QA的数据库绑定，防止QA入口误读默认数据库。
`driver_amendment.json`保留修订前后哈希和说明，先前冻结驱动也原样归档。
