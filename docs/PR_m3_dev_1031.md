# feat(m3): 优化增量事实检索，修复全片段采样并接通单视频人物关联

## 概述

本 PR 面向 M3 多模态记忆与问答，解决重复证据导致的上下文膨胀、片段尾部未被采样、单片段失败阻断下游，以及人脸处理随账号内视频累积反复重算的问题。

在已有多模态管线与预算模块上，补充来源事实索引、严格增量交付、回答收尾与覆盖回执，并建立“单视频人脸观测 → 人物关联 → 情景事实 → QA”的可追溯关系链。

**不包含 PR #300 的并发整合。** 并发改动在后续 `intergation_1103` 分支单独提交。

## 主要改动

### 1. 控制问答上下文与 token 开销

- 扩展已有上下文预算机制：原文分组、可见证据审计、来源事实表示和增量交付。
- 只依据真正交付给模型的原文位置进行去重、增量计数和停止判断；曾检索到但未展示的事实仍可在后续准入。
- 修复增量额度被非模型可见的审计字段放大的问题，按实际模型投影计数；全局预算仍覆盖完整保留历史。
- 保留事实来源、内容 hash、原文范围及时间边界；不额外调用聊天模型生成压缩摘要。
- 终轮及可选的时间预留阶段关闭 Search，保留 Answer 机会；不增加轮次、不要求猜测。provider 支持时可请求 `required`，仍保留合法文本兼容路径。
- 新增配置生成工具：校验 tokenizer 指纹，生成权限为 0600 的新配置副本，不覆盖原配置、不更换模型或连接。

### 2. 新增可复用的来源事实索引

- 新增 `python -m m3.build_fact_index`，从既有情景描述、ASR 与结构化字段提取原文事实窗口。
- SQL 读取使用只读事务，按账号、视频、节点类型过滤，不触发建表或原记忆写入。
- 使用配置的 embedding 服务构建旁路索引，安全发布带 manifest/hash 的不可变产物；查询时重新验证来源节点与时间范围。
- 事实召回与原片段检索软融合；姓名/角色声明不是已验证身份，不作为硬过滤条件。

### 3. 修复 30 秒片段只覆盖前半段的采样问题

- 全流程按 1 fps 收集每个 30 秒片段的最多 30 帧，CLI 与 YAML 默认值同步修正。
- 情景模型仍从完整采集帧中均匀选择最多 16 张基础帧。标准片段的模型时间范围由约 **0–15 秒**扩展至约 **0–28 秒**。
- 人脸检测覆盖收集帧，完整音频不截短。
- 这里改善的是时间覆盖，并非每一秒都送入模型，也不保证捕获所有短暂动作。

### 4. 单片段失败的可审计降级与恢复

- 对域校验识别的无效情景输出增加有上限的重试；不放宽 JSON/内容校验，不把鉴权、数据库错误当成格式错误重试。
- 显式配置 `failure_policy: continue` 且通过一致性校验、覆盖率达到阈值时，允许成功片段继续索引和 QA；完整管线阈值为 95%。
- 生成绑定账号、视频、数据库标识及产物 hash 的 `memory_coverage.json`，在 QA 提示和输出中披露缺失片段。
- 拒绝失败片段的旧记忆混入；不完整运行仍返回非零，不将部分答案视为完整续跑凭据。

### 5. 单视频人物关联与检索

- SQL/内存存储在分页前按视频过滤；独立人脸聚类入口要求指定单个视频，避免加载并重复聚类整个账号的人脸。
- 为旧缓存的人脸节点验证、补齐视频/片段来源，不重复调用 CV。
- 完整管线在情景生成前，按观测时间建立有限样本的匿名视觉身份候选；后来的姓名/观测不能反向改写过去的证据。
- 当前片段可额外输入最多 8 张有标签的人脸裁剪，将验证过的输入 ID 写入人物/事件绑定，并通过图谱引用保存来源。
- QA 可按来源支持的姓名声明或已观察到的匿名 ID 扩展同人物事实，与原检索软融合；歧义姓名、冲突身份、过期来源不用于姓名扩展。
- 视觉身份仍是候选，姓名/事件归属仍是模型声明，不宣称完成了脸—声音—姓名认证。

## 已有评测结果

以下使用 **MiniMax-M3.1-Flash / adaptive / medium**。固定五个开发视频、65 题；oGMemory 各组使用同一份既有记忆，仅重跑 QA，输出预算保持 8192。分数为共同自动评委的 **0 / 0.5 / 1 均分**，不是人工准确率。

**两批实验分别展示，不跨批选择较高评分；这些结果验证 PR 内相应方案，不代表当前完整分支相对 dev 的端到端单因素消融。**

### A. 上下文预算与回答收尾

| 方案 | 有效回答 | 自动评分均值 | QA 输入 token | 单请求输入峰值 |
|---|---:|---:|---:|---:|
| 原 QA 固定轨迹 | 59/65 | 0.5385 | 19,905,749 | 156,689 |
| balanced：预算 + 回答收尾 | 65/65 | 0.6077 | 4,804,362 | 16,922 |
| balanced 独立重复 | 65/65 | 0.5769 | 4,707,523 | 16,927 |

- 首次 balanced 的 QA 输入减少 **75.9%**，单请求峰值减少 **89.2%**。
- 两次 balanced 均完成 65/65 有效回答；该批原先有 6 题超时，新轨迹未出现 QA 超时。
- 不能由此声称稳定显著提分：仅五个开发视频，相关整视频簇区间包含零，原已回答题也存在回归。
- 45 秒时间预留在这批实验中未触发，不能将改善归因于该计时机制。超时仍是软预算，不是 HTTP 硬取消。

### B. 来源事实与严格增量交付

另一批共同评分中，相同五视频上的同期对照如下：

| 方案 | 有效回答 | 自动评分均值 | QA 输入 token | 其中未缓存输入 |
|---|---:|---:|---:|---:|
| 同期 balanced | 65/65 | 0.5308 | 4,721,119 | 4,136,779 |
| E：来源事实 + 严格增量 3500 | 65/65 | 0.5846 | 2,915,704 | 1,507,722 |
| M3-Agent 同模型参考适配重复 | 65/65 | 0.4615 | 551,699 | 196,999 |

- E 相对同期 balanced，QA 输入减少 **38.2%**，未缓存输入减少 **63.6%**。
- 370 次 QA 调用均满足配置的严格增量上限；305 次相邻请求消息前缀检查全部保持。该检查不包含工具 schema，不等价于供应商 KV 命中保证。
- E 只有一次完整运行，定位为低输入开销候选，不宣称已证明稳定准确率增益。
- M3-Agent 是同模型参考协议适配，不是官方权重复现；E 的 QA 输入仍明显高于 M3-Agent。上述百分比是相对 **oGMemory balanced**，不是相对 M3-Agent。
- token 统计只含 QA；不等价于完整管线 token、费用或端到端耗时下降。

### C. 抽帧、可靠性与单视频人脸处理的验证

- **抽帧覆盖**：标准 30 帧片段选 16 帧后覆盖约 0–28 秒；有抽帧回归测试和十视频实验逐片段帧时间审计。不单独宣称采样改动带来多少准确率增益。
- **故障注入**：在隔离的 SQL 克隆库中，强制 `study_18` 的一个片段连续输出无效，其余 83/84 个片段继续索引并进入 QA，覆盖回执正确。QA 为 stub，此项验证降级控制流，不是模型质量评测。
- **真实数据只读检查**：`study_18` 在账号共 24,083 条人脸中仅选取本视频 4,467 条（本次选取集合减少 **81.5%**）；4,422 条有效观测的因果匹配约 11.13 秒，552 条前缀观测赋值在加入后续观测后保持一致。
- 上述人脸检查在内存中恢复旧来源、不写实验库；不等于生产 SQL 全链路加速比，也不是身份准确率评测。最新人物关联尚无可归属于本 PR 的端到端 QA 增益结论。

## 兼容性与使用

- 新的事实/增量 QA 配置默认 opt-in，不自动替换现有 QA 策略；通用生成/QA 构造器的人物能力也默认关闭。
- **完整管线配置有行为变化**：抽帧上限改为 30，启用人物关联/人物检索、无效输出重试及受控降级；人脸聚类提前到情景生成之前。
- 人脸聚类独立命令需要单视频参数；新增 `GraphStore.list_nodes(video_id=...)` 可选过滤接口。
- 人物裁剪会增加图片输入；本 PR 不保证新完整管线的记忆生成 token 下降。
- 使用新工作目录与独立评测数据库；人物上下文变化后重新生成记忆/构建索引，不混用旧事实索引，不在不同策略之间直接 resume 旧答案。
- 统一使用与测试说明：`docs/multimodal_memory.md`。详细设计和历史实验移至独立评测仓维护。

## 本 PR 不宣称

- 十视频结果已验证最新人物关联的准确率提升；
- 并发分支的加速收益属于本 PR；
- 局部 token 下降等于整体费用同比下降；
- 自动评分改善已经获得独立留出集或人工评估确认。
