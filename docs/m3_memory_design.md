# 第二轮：来源事实、显式人物条件与增量交付

日期：2026-11-02。本页描述已实现的机制；质量结论以
`experiments/m3_memory_design_20261102/` 的完整实验及共同评分为准。

## 1. 不把截短文本误称为语义记忆

第一版F将已有episodic记忆拆成可定位的原文单位：

- 连续两句description；
- 相邻三条ASR窗口，完整保留局部speaker标签和时间；
- 单条event、character或entity原始对象。

没有新增LLM总结，也不产生原来记忆没有的高层推断。来源以完整投影的
内容hash、节点ID、视频、片段可用时间、字段/数组索引或字符范围记录。
重叠ASR窗口按来源位置去重，不按文本内容去重：同一句话在不同时间
出现，仍是不同观察。位置索引不能当成事件数量或跨片段人物ID。

F的单位选择仍然发生在片段召回之后，因此它本身不是独立事实召回层。
后续S组才加入真正可检索的来源事实向量旁路。

## 2. 显式人物条件：有帮助，但不是身份解析的终点

FI在已经按账号/视频/时间过滤的候选片段内，检测查询中完整匹配的
character.name或character.role。以有界软排序奖励匹配候选，同时保留
无匹配候选，避免把“未写姓名”误当成“不是此人”。
已匹配的人物原始描述也会获得证据准入优先级。

边界：

- 不把SPEAKER_00、VOICE_x、FACE_x字符串当成跨片段姓名；
- 不因为两个片段都写coach就合并身份；
- 不把呼叫Alice自动解释成说话人Alice；
- 不读取未来片段建立姓名或聚类映射；
- 这里利用的是来源中的人物声明，不是已核实的人脸—声音等价关系。

现有生成记忆没有稳定身份锚点与姓名的绑定关系，因此本轮不能诚实地
声称已经复现M3-Agent的多模态人物解析。下一阶段应在生成端加入锚点、
可撤销关联和逐条可用时间，再独立评估关联错误。

## 3. 增量交付

每个问题独立维护工具消息投影和已真正交付的来源位置。

1. 过去已交付的工具消息原样保留，不随最新查询重新改写。
2. 新Search仍可返回同片段，但只准入未交付的事实。
3. 新事实使用独立证据ID，不覆盖先前同源片段的证据定义。
4. 初版配置的新增额度为5000；同时遵守整体22528有效输入上限。
5. 接近总预算时，从完整原始Search审计重建一个新的上下文epoch，
   重置交付集合，重新检查引用，绝不引用已经移出的正文。
6. 原始消息改变会使缓存整体失效；不同问题之间清空状态。

首版FIP仍沿用基于新增节点ID的no-gain控制。后续S组修正为
实际新增可见事实的连续轮次；单轮多个Search合并观察一次。
Search调用数上限、最终Answer-only以及时间预留仍独立有效。
S记录实际模型消息的逐消息hash，便于验证前缀稳定性，不保存凭据。

缓存命中率仍由服务商实现和实际请求决定；“保持消息不变”不意味着
保证命中缓存，更不意味着费用或延迟按相同比例降低。

**03:34后发现并修正的计数缺陷：**首版的新增额度基数混入了最后不会发送给模型的
检索审计字段，名义5000不等价于严格新增5000。离线反例在1000配置下出现7095
代理单位的证据增量，但总输入上限仍有效。修复改为从实际空证据模型投影计数，
增加严格准入上限，并避免在没有新检索结果时仅因余量较小而重建。
旧FIP/S轨迹不修改；修复另冻结E组。E采用3500增量及原生required收尾，
不启用场景锚点，只参加共同评委。旧I/H快照在执行前被标记替代。

## 4. 来源事实旁路索引

S组使用相同GPU BGE-M3嵌入原文事实窗口，保存只读NumPy矩阵与JSON清单。
它不替换原SQL图和片段向量索引，不改写任何原记忆。

查询时：

1. 先按账号、视频、片段上界和完整来源片段结束时间筛选事实；
2. 计算事实向量相似度，按源节点max-pool，并保留每个节点最相关的三个窗口；
3. 通过GraphService按片段精确读取，重新执行账号、类型和时间限制；
4. 校验实际源节点完整内容hash；陈旧或不匹配记录丢弃；
5. 与原向量+转写混合召回做等权排名融合，再执行显式人物软排序；
6. 最终仍受节点数上限约束；命中的事实位置获得证据准入优先级。

索引清单和向量文件都有固定SHA256，禁止pickle和任意向量文件路径。
原文、事实位置和源可用时间保留。不会把整片段的人物名单附加到每条事实上，
也不会将只凭后半段才能确认的视觉摘要按单句时间提前开放。

由于S同时含事实召回、可见事实停止条件与审计增强，相对FIP的效果差异
不能全部归因于向量索引。索引构建耗时和存储开销单列于实验receipt。
最初准备的2:1融合版本在正式运行前被代码复查否决：满候选池时它会压制
所有仅由事实索引找到的新节点。保留未运行版本清单，正式S采用v2等权版本。

## 5. 评测纪律

全部开关默认关闭，保留原balanced配置。固定原五视频65题、模型和评委，
保留全部失败，不按题择优重跑。旧balanced与M3答案只参与对照评分，
不参与新索引、记忆或检索构建。视频是开发集，不据此声称全数据集泛化。

## 6. 后续诊断配置（是否实际执行以实验清单为准）

### I：保留balanced的叙事单位，仅改交付

I保留完整短片段description与相邻转写的原有成组方式、passages表示和
每节点32条上限，只开启增量交付及其可见事实停止条件。它不使用事实索引或
名字软排序，目的是检查收益/损失是否来自交付机制，而不是把所有变化归为压缩。

增量准入已修复一个边界：叙事已经在旧工具结果中可见时，新的工具结果可以
只补充同源entity/character，无须再次展示叙事。已移出上下文的叙事不能触发
这种许可。原始问题没有姓名时，当前Search明确检索某人的查询也可以提高其
有来源人物描述的准入优先级；这不推断名字与人脸/声音的等价关系。

### H：保留场景上下文并约束最后的工具调用

H在S基础上，把每个新片段的最初两段按标点切分的description原文附在短事实
旁边（原文及包装共2048 bytes上限），作为场景/人物上下文；已经展示的原文
位置不重复追加。相关性仍按候选事实本身排序，场景文本不是新推断。
切分是简单标点规则，不应宣称具有完整语言学句子边界处理。

H另开启`force_answer_tool`：Search关闭时，API设置`tool_choice=required`，
并且schema只提供Answer。未关闭Search时仍是auto；禁用工具的轮次仍是none。
用户必须使用支持该请求的服务，默认关闭，不自动更换模型或重试一条成功答案。
MiniMax小型非benchmark探针验证了协议支持，但不能据此保证事实正确或推理正确。

这是组合诊断配置，而不是“只改变一个缓存参数”。若因额度/截止限制未运行，
只能报告实现和单测，不能把它写成已验证的提分方案。

## 7. 配置与可复现边界

配置均位于`m3.qa_context`，现有`balanced`不自动启用新功能：

| 设置 | 作用 |
|---|---|
| `fact_memory` | 原文事实/连续转写窗口替代完整短叙事选择 |
| `identity_aware` | 显式名字/角色软排序及人物原文准入 |
| `incremental_delivery` | 问题内稳定工具消息与未交付来源位置账本 |
| `incremental_tokens` | 每轮新增证据代理token额度，默认5000 |
| `fact_index_path` + `fact_index_sha256` | 固定清单及其向量文件完整性验证 |
| `fact_scene_anchors` | 给短事实保留有来源场景上下文，要求fact_memory和至少3条容量 |
| `force_answer_tool` | 仅在Search关闭时要求原生Answer工具调用 |

本轮F/FI/FIP采用grouped表示、每节点12条；S在此基础上加入索引与可见事实停止修正。
I采用passages/32条。不能把某个配置的较高分与另一个配置的较低开销拼接。
每组确切源码、配置、tokenizer、索引hash见对应manifest；不要用当前HEAD替代归档。
外层`run_context_experiment.py`接受显式截止时间环境变量
`M3_EXPERIMENT_DEADLINE`，运行冻结runner时还需`M3_EVAL_ROOT`。
换配置必须新建实验名和输出目录，不对旧答案直接resume。

旁路索引的当前实现使用本地密集NumPy矩阵，只适合本轮规模的原型验证。
它不提供生产级增量更新或大规模ANN；源内容改变后会拒绝陈旧记录，需要重建索引。
后续应考虑账号/视频分片和事实级持久化向量索引，但这不是本轮已实现能力。
新M3参考重复同样只重跑QA，不再生成媒体、感知或记忆；独立轨迹全部报告。
