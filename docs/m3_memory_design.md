# 第二轮：来源事实、显式人物条件与增量交付

日期：2026-11-02。本页描述已实现的机制；质量结论以
`experiments/m3_memory_design_20261102/` 的完整实验及共同评分为准。

## 1. 不把截短文本误称为语义记忆

第一版F将已有episodic记忆拆成可定位的原文单位：

- 连续两句description；
- 相邻三条ASR窗口，完整保留局部speaker标签和时间；
- 单条event、character或entity原始对象。

没有新增LLM总结，也不产生原来记忆没有的高层推断。来源以完整投影的
内容hash、节点ID、视频、片段可用时间、字段/数组索引或字符范围记录。
重叠ASR窗口按来源位置去重，不按文本内容去重：同一句话在不同时间
出现，仍是不同观察。位置索引不能当成事件数量或跨片段人物ID。

F的单位选择仍然发生在片段召回之后，因此它本身不是独立事实召回层。
后续S组才加入真正可检索的来源事实向量旁路。

## 2. 显式人物条件：有帮助，但不是身份解析的终点

FI在已经按账号/视频/时间过滤的候选片段内，检测查询中完整匹配的
character.name或character.role。以有界软排序奖励匹配候选，同时保留
无匹配候选，避免把“未写姓名”误当成“不是此人”。
已匹配的人物原始描述也会获得证据准入优先级。

边界：

- 不把SPEAKER_00、VOICE_x、FACE_x字符串当成跨片段姓名；
- 不因为两个片段都写coach就合并身份；
- 不把呼叫Alice自动解释成说话人Alice；
- 不读取未来片段建立姓名或聚类映射；
- 这里利用的是来源中的人物声明，不是已核实的人脸—声音等价关系。

现有生成记忆没有稳定身份锚点与姓名的绑定关系，因此本轮不能诚实地
声称已经复现M3-Agent的多模态人物解析。下一阶段应在生成端加入锚点、
可撤销关联和逐条可用时间，再独立评估关联错误。

## 3. 增量交付

每个问题独立维护工具消息投影和已真正交付的来源位置。

1. 过去已交付的工具消息原样保留，不随最新查询重新改写。
2. 新Search仍可返回同片段，但只准入未交付的事实。
3. 新事实使用独立证据ID，不覆盖先前同源片段的证据定义。
4. 每轮新增证据估计额度5000；同时遵守整体22528有效输入上限。
5. 接近总预算时，从完整原始Search审计重建一个新的上下文epoch，
   重置交付集合，重新检查引用，绝不引用已经移出的正文。
6. 原始消息改变会使缓存整体失效；不同问题之间清空状态。

首版FIP仍沿用基于新增节点ID的no-gain控制。后续S组修正为
实际新增可见事实的连续轮次；单轮多个Search合并观察一次。
Search调用数上限、最终Answer-only以及时间预留仍独立有效。
S记录实际模型消息的逐消息hash，便于验证前缀稳定性，不保存凭据。

缓存命中率仍由服务商实现和实际请求决定；“保持消息不变”不意味着
保证命中缓存，更不意味着费用或延迟按相同比例降低。

## 4. 来源事实旁路索引

S组使用相同GPU BGE-M3嵌入原文事实窗口，保存只读NumPy矩阵与JSON清单。
它不替换原SQL图和片段向量索引，不改写任何原记忆。

查询时：

1. 先按账号、视频、片段上界和完整来源片段结束时间筛选事实；
2. 计算事实向量相似度，按源节点max-pool，并保留每个节点最相关的三个窗口；
3. 通过GraphService按片段精确读取，重新执行账号、类型和时间限制；
4. 校验实际源节点完整内容hash；陈旧或不匹配记录丢弃；
5. 与原向量+转写混合召回做2:1排名融合，再执行显式人物软排序；
6. 最终仍受节点数上限约束；命中的事实位置获得证据准入优先级。

索引清单和向量文件都有固定SHA256，禁止pickle和任意向量文件路径。
原文、事实位置和源可用时间保留。不会把整片段的人物名单附加到每条事实上，
也不会将只凭后半段才能确认的视觉摘要按单句时间提前开放。

由于S同时含事实召回、可见事实停止条件与审计增强，相对FIP的效果差异
不能全部归因于向量索引。索引构建耗时和存储开销单列于实验receipt。

## 5. 评测纪律

全部开关默认关闭，保留原balanced配置。固定原五视频65题、模型和评委，
保留全部失败，不按题择优重跑。旧balanced与M3答案只参与对照评分，
不参与新索引、记忆或检索构建。视频是开发集，不据此声称全数据集泛化。
