# M3-Agent 同模型端到端适配对照：执行协议

日期：2026-11-01。本文件是对已冻结参数和实现的补录，**不是事前注册声明**。
启动前确定的配置、样本与源码指纹分别见 `provenance.json`、
`sample_manifest.json`、`adapter_source_hashes.json`。

## 范围

本次为 **M3-Agent-style + MiniMax 的适配版**，不是官方 Memorization/Control
权重复现。使用同一 5 个 robot 视频和 65 题，从原始媒体重新执行感知、身份匹配、
记忆生成、检索、问答和评分，不读取 oGMemory 的情景/语义记忆，
不读取数据集预生成图或中间结果。

参考仓库及 oGMemory 感知源代码已冻结到 `runs/.../_source/`；
运行适配器冻结到 `_adapter/`。后续 `m3_dev_1031` 上的容错修改不改变本轮代码。
原 `m3-agent/` checkout 未修改，也未执行其全局安装脚本。

## 统一的条件

- 同一抽样清单：study_05、gym_03、bedroom_04、study_18、kitchen_20。
- 原始视频、全时长、30 秒片段；1 fps 前缀至多 16 帧，512 缩放，JPEG 80。
- 相同本地 CV、Whisper large-v3-turbo、pyannote、ECAPA；在新数据库/新目录重算，
  不复用首轮感知产物。模型权重缓存和已有 GPU 服务可以复用。
- 相同 MiniMax-M3.1-Flash、adaptive/medium，记忆/QA 8192、评委 2048。
- 相同 BGE-M3 1024 维服务；所有 M3 文本记忆重新嵌入，不混用官方旧向量。
- 记忆调用最多 4 并发；QA 6 轮、180 秒循环预算、300 秒单请求超时。
- 采用相同 `current_clip` 可见性，以实际 source interval 解析 timestamp；
  没有时间限制的全视频问题允许全部片段。
- 使用同一个 `m3.eval` 和相同 `{0,0.5,1}` 提示评分；不是参考代码的二值 GPT-4o 成绩。
- 完成后对两组固定预测在同一阶段重新评分，保留原分数，不取最高分。
  oGMemory 固定预测为四个首轮视频 + study_18 定向恢复的首次完整答案。

## 保留的参考机制

`reference.py` 从固定源文件中提取并执行真实的函数/类 AST：

- VideoGraph 及其实体匹配、边权强化/弱化、身份等价合并；
- `parse_video_caption` 和 Qwen 路径中的 `process_memories`；
- `translate`、`back_translate`、实体候选约束、片段聚合以及原 `search`。

函数/类主体不重写。AST 选择仅避免 `mmagent.__init__` 及模块顶层
自动加载权重、初始化其他 API 与 GUI。所有源文件哈希与定义名有单独回执。
嵌入回调明确替换为 BGE-M3，不把接口中遗留的模型字符串当作真实服务模型。

逐片段产生原子事件与高层语义事实，并保留 `Equivalence: <face_x>, <voice_y>`。
正常检索仍为 2 个片段、阈值 0.5；名字/ID 查询走 20 条 memory-wise 路径，
已见片段去重。语义相似阈值 0.85/0 与 face/voice 匹配阈值 0.3/0.6 沿用参考代码，
没有依据本批答案调参；更换嵌入后的阈值校准尚未验证。

## 必须披露的适配因素

1. 官方权重换成 MiniMax，视频输入换成与 oGMemory 相同的采样帧及原始音频。
2. M3 的身份提示额外带最多 8 个带 ID 的人脸裁剪，这是其方法特有输入，
   **不是两边图像输入量完全相同的单变量实验**。额外图像与 tokens 会记录。
3. CV 框坐标按共享后端的归一化契约裁剪，已做尺寸测试。
4. 为统一感知，不沿用参考的 Gemini 分段、ERes2NetV2 或基于 5 fps 的
   HDBSCAN/质量过滤；新感知结果再交给参考的跨片段匹配函数。
5. 先按时间顺序准备身份锚点和各片段提示，再并发生成独立片段记忆；
   语义图更新仍按片段时间顺序执行。数值 ID 分配与串行原版不要求逐字相同。
6. 修正提示中的单数 `video_description` 与读取端复数 `video_descriptions`
   的接口差异；允许无歧义别名转换，不编造事实。
7. 使用原生 Search/Answer 工具和共用 ReAct 循环替代专门训练控制器的文本动作解析。
   提示保留名字/character ID 查询逻辑，但停止行为、提示和训练策略不等同于原版；
   不保留原版末轮“可以猜测”的要求。这是适配因素，不应把控制失败直接归因于记忆图。
8. 每题从可见片段重新构建语义前缀，防止较晚片段强化早期边权后残留在历史问题中。
9. 已接受的成功记忆仅在输入/模型哈希完全相同时续用；重试不改变预算。
   域无效输出最多额外一次，瞬时 HTTP 错误有界重试。低于 95% 覆盖不运行 QA；
   允许部分覆盖时在提示和每题结果中披露。

## 时间与成绩解释

这是一轮开发式端到端运行，包含真实预检、并行感知及共享远端服务。
两个预检片段属于同一配置下的首次生成，正式运行按输入哈希复用它们，未择优。
总墙钟包含开发停顿、缓存及远端负载变化，**不能直接用来宣称架构加速倍数**。
同时保留模型调用次数、模态数量、输入/输出用量及控制失败类型。

当前已经看到控制器在部分问题上到达轮数上限但不提交答案；这些题如实记失败，
不会被当作已回答，也不在中途偷偷修改控制器后混合不同条件。
如果做末轮提交或共同控制器消融，将使用另一组 QA 输出、对所有 65 题统一运行，
并标明冻结记忆后只改变控制部分。
