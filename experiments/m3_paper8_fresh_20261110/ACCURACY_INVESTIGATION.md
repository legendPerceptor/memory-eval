# 新旧八视频失分排查：初步证据

本记录检查已有实验，不是新运行的消融实验。旧版为 `runs/m3_ten_fullinterval_20261102`，新版为 `runs/m3_paper8_fresh_20261110`；按已有同批盲评，新版 50.52%，旧版 55.15%，每题得分为 0、0.5 或 1。旧版提交、输出上限、人物处理、记忆内容、索引、问答策略及运行时间窗口都不完全相同，不能从总体分差确定单一原因。

## 分差视频和具体问题

| 视频 | 题数 | 旧版 | 新版 | 有代表性的失分 |
| --- | ---: | ---: | ---: | --- |
| kitchen_01 | 13 | 38.5% | 26.9% | Q06 协议文本导致失败；Q02 旧版作出人物推断、新版认为不能确定 |
| bedroom_05 | 12 | 41.7% | 29.2% | Q11 旧版根据最后清理工具的对话推断归还位置，新版只回答擦拭时的位置 |
| kitchen_23 | 12 | 54.2% | 41.7% | Q02 新版认为数量无法确定；Q08 将两个鸡蛋答成三个；Q03、Q09 存在部分分差 |
| study_23 | 14 | 60.7% | 53.6% | Q02 协议失败；Q12 把人物榜样理解成汽车模型；Q14 两个位置答成一个 |

旧版的一些正确答案本身含推断，并非已经人工核实的因果证据。部分评分可能对措辞敏感：例如 `kitchen_23_Q03` 两版都回答看屏幕太久，旧版得 1、新版得 0.5；`kitchen_23_Q09` 两版均提到将四分之三鸡蛋给对方，得分分别为 1 和 0.5。不能把这两例直接归因于系统性能。

### 记忆内容与检索方向

- `study_23_Q12`：新旧 episodic memory 的第 20 片段都包含 “He is a model for me” 和 Paul。旧版搜索轨迹第三轮开始搜索 Paul 和榜样，新版六轮集中在汽车模型及 Ferrari；最终旧答 Paul，新答 Ferrari。说明正确线索没有在整个新版记忆中消失，且轨迹出现明显的语义方向差异；不能据此证明它进入了新版模型上下文，也不能排除索引或人物关联影响了第一轮搜索。
- `bedroom_05_Q11`：新旧第 59 片段都包含 “cleaning up tools into the storage room”。旧版第四轮搜索清理工具和储藏室，新版搜索集中在抹布、桌面和擦拭位置；旧版推断归还储藏室，新版答留在地面附近。该片段反映对工具的总体描述，并不能单凭文本断定抹布一定在内；上述现象说明需进一步审计召回和推断，不证明检索预算或索引为唯一原因。
- `kitchen_23_Q08`：旧版检索包含 “two eggs boiled pot”，新版检索第三轮包含 “three eggs”，两者最终分别答二和三。这个轨迹与数量推断分歧一致，但无法确定错误从记忆、检索结果还是模型推理开始。
- `kitchen_01_Q06`、`study_23_Q02` 是输出包含 Search/Answer 协议文本而被判失败；应独立于人脸和嵌入问题处理。不能将格式失败自动等同于检索失败。

搜索日志保存查询、节点 ID 和上下文节点 ID，但本次未能从上述片段的原始或提取节点 ID 直接匹配出日志上下文；因此未确认每个片段实际上是否送入模型。后续应记录检索节点到 clip 的映射、各轮排序及预算截断后的最终文本。

## 人脸处理并非语义等价

四个重点视频的新旧 `faces.jsonl` 哈希相同，但人脸聚类实现及输入范围不同。旧版摘要中的 faces 包含既有成员，不可视为当前视频的人脸数；新版为 `video_local_causal_proposals`：

| 视频 | 旧聚类总耗时 / faces / existing_members | 新聚类总耗时 / faces / people |
| --- | --- | --- |
| kitchen_01 | 446.59 s / 4,776 / 1,729 | 16.72 s / 2,766 / 1,768 |
| bedroom_05 | 818.35 s / 6,440 / 4,029 | 8.50 s / 1,628 / 857 |
| study_23 | 1,326.60 s / 8,275 / 5,482 | 9.86 s / 1,826 / 784 |
| kitchen_23 | 1,948.04 s / 10,005 / 7,177 | 9.03 s / 1,723 / 989 |

这些是各自日志中的阶段耗时，旧版含既有成员且运行条件不同；不是严格配对的性能测试。新版 `people` 是算法产生的身份数量，不等于真实人数。这种跨视频范围到单视频因果候选的变化并不保证人物关系等价，不能称为纯性能优化；但目前也没有证据证明它导致上述失分。新旧 episodic memory 的文件哈希不同，新版还含 person grounding；须在同一其余条件下消融。

## 已有精简索引重放

`experiments/m3_compact_replay_20261109/` 在另一批 `m3_dev_1031` 记忆上复用原图和事实索引，建立独立精简向量表并重答；128 题统一盲评平均分原始 51.17%、精简 49.61%。重点视频分别为 kitchen_01 23.08%→46.15%、bedroom_05 37.50%→29.17%、study_23 60.71%→57.14%、kitchen_23 33.33%→50.00%。本次重放亦复制了 `control_adapter.py` 等代码，且每组只有一次问答，不能当作严格的仅嵌入文本单因素消融。它没有证明精简索引能稳定保分，也没有证明必然损害得分。

## 可复现条件与下一步

旧、新图与向量配置分别指向不同的 PostgreSQL 数据库，两边连接成功，`m3_episodic_vectors` 表均存在；旧、新代码快照及结果文件也仍在。表存在不代表记录完整、数据未变、向量服务和模型后端可逐位复现；还需校验账户下图节点、向量行数和索引版本，固定配置及模型，重跑同一组多次估计自然波动。不能承诺非确定性 API 精确复现旧分数。

建议优先在上述四视频分阶段实施：

1. 冻结新记忆和图，建立两个独立向量表，仅更换完整与精简嵌入文本；固定同一版 QA、配置、模型和检索策略。重复回答、记录每轮 query、命中片段、排序、截断及最终证据；随机混合盲评并人工复核有争议题。
2. 同一数据库和完整索引下对比旧版及新版 QA 策略，并交叉到精简索引，隔离 QA 策略与索引的交互。若新旧代码还包含其他差异，应使用最小开关或明确列出无法消除的混杂项。
3. 对人脸建立独立账号或数据库，以相同感知输入、模型与其他配置分别构建两套记忆，比较人物候选、绑定、记忆内容、建忆 token 与耗时，再在固定 QA/索引下评估。必要时再交叉索引，不覆盖原库。
4. 各组固定全视频题集，失败不丢弃，单列协议失败；记录调用 token、各阶段时间、额度等待、成本及来源。以每视频和逐题配对结果报告不确定性，优先准确率，不把少量题的随机起伏当作结论。

截至本记录，以上新消融尚未启动或完成；本记录不是八小时实验结果。
