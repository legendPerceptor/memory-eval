## 方法与限制

- 多模态证据 → 情景 ExtractedNode → 片段/视频 MemoryNode；BGE-M3 向量、转写词法召回、RRF、邻近片段、ReAct QA。
- 默认 QA 主检索片段情景记忆，不能将身份图/语义汇总的生成等同于已经验证它们有质量增益。
- 每 30 秒片段的画面主要覆盖前约 0–15 秒；完整音频不弥补所有视觉遗漏。
- current_clip 允许看到问题所在片段末尾，非严格因果评测。
- 只测五个 robot 视频，study_05 为已用开发样本，不代表整个 M3-Bench。
- 正式模型使用 medium 推理强度；前序 max 和 Omni 没有完整质量成绩，不能计算新模型相对它们的提升百分比。
- 暂未启用有界 QA 上下文；后续可冻结记忆做独立消融。

### 明确发现

| 问题 | 金标与回答差异 | 临时评分 | 解读 |
|---|---|---:|---|
| Q01 彩纸位置 | 金标为最右书柜顶层抽屉；回答桌面 | 0 | 初始存放位置与随后使用位置混淆；尚不能单凭答案区分采帧遗漏、抽取遗漏还是检索错误 |
| Q02 工具箱物品 | 金标剪刀和胶水；回答实际从箱中取出的只有剪刀 | 0.5 | 提到胶水却排除其来源，证据整合不完整 |
| Q03 树的总数 | 金标 1；回答 2，并引用“再做一棵”的计划 | 0 | 将意图/计划当作已经发生的事件 |
| Q05 树干步骤 | 金标 3；回答 3 | 1 | 答案数值匹配；理由中引用的数数语句仍需视频级核实，不能仅凭匹配证明推理正确 |
| Q06 书包位置 | 金标在桌子左侧；回答桌面 | 0.5 | 评委把空间偏差给了半分，评分可能偏宽 |
| Q08 主要步骤 | 金标 5；回答 3 | 0 | 动作粒度和步骤合并可能影响计数，不能用检索到的几类动作替代标注步骤总数 |
| Q09 装饰材料 | 金标黏土苹果；回答纸苹果及其他装饰 | 0.5 | 对象类别部分正确，但关键材质错误 |
| Q10 笔筒物品 | 金标铅笔；回答笔/铅笔/马克笔等宽泛集合 | 0.5 | 回答不够精确，枚举可能物品不等于明确识别 |

Q04 的“平时是否经常争吵”回答 no，与金标一致，临时评委给满分。
Q07 树叶步骤、Q11 是否只关心学习、Q12 剪刀使用次数没有有效答案，循环超时；
它们不是评委 API 失败，也不能作为已经正确检索但未评分的问题。

### 上下文与耗时

首视频 QA 共 60 次逻辑模型调用，累计输入 3,994,009 tokens，
单次输入峰值 **147,951 tokens**。这些是实际 API usage，不是本地字符估算。
三题超时同时伴随长检索对话；它支持检查上下文累积和无效重复检索的必要性，
但不能单凭相关性断言所有超时都由上下文大小造成。
没有观察到这 60 次调用的 API 级错误或输出 length；循环超时与 HTTP 超时应分开。

69 条情景记忆均新生成成功、无复用、无失败；69 条索引已建立。
记忆阶段约 51.4 分钟（相邻阶段日志差），随后还需问答与其他阶段。
因此“换更大模型＋记忆写完”并不意味着 QA 质量已经验收通过。
